### 检查 11 为何判 FAIL：它是其余 SVG 检查的前提（lead 裁定，2026-08）

`<text x=100>`（属性不加引号）浏览器照常渲染——内联 SVG 走 HTML 解析器，不走 XML 解析器。曾据此把它记为"假阳性"，但实测推翻了这个定性：

| 同一张 SVG 里同时注入 | 检查是否仍生效 |
|---|---|
| 硬编码色 `fill="#FF0000"` | ✅ 检查 9 照常抓到（它走 HTML DOM，不依赖 XML 解析） |
| 越界文本 `x="900"` | ❌ **检查 12 静默失效**（`ET.fromstring` 失败即跳过整块） |

所以 XML 严格合法**是检查 12 的前提条件**，不是单纯的风格口味：一个 XML 非法的块会让该图的几何检查悄悄下线，而页面看上去一切正常。判 FAIL 成立。

注：lead 给的建议文案作"色值/文本检查将全部失效"，据上表**色值检查其实不受影响**，已按实测改写为只点名检查 12，避免文案夸大导致作者不信任报错。

### 检查 12 的边界（阈值与已知盲区）

- 阈值：越界容差 `MARGIN=4px`，重叠需两轴各交叠 `>6px`。pilot 用 ±2px 在两章零误报，我放宽到 4/6 以换取全书稳定，代价是漏掉极轻微擦边。
- 字宽为估算（CJK≈1.0em，西文≈0.55em，mono 数字≈0.6em），**误差约 ±8%**，故一律 WARN。
- 带 `transform`（含**任一祖先**）、`dx/dy`、`textLength`、`<tspan>` 自带定位、缺 `x`/`y` 的文本一律列入"需人眼"清单，**不当作通过**（lead 明确要求）。祖先 transform 靠 child→parent 表回溯，不是只看自身。
- 只查 text↔text，不查 text↔图形（后者噪声极大：图例文字本就紧贴色块）。
- 看不见 `filter`/`mask`/JS 动态改坐标造成的位移。

## 复现方式

变异树由一次性脚本生成，不留在项目内。复现步骤：

1. 建临时目录，**必须**放入 `assets/style.css` + 目标章 HTML（保持 `chapters/` 子目录）；测 index 相关项时再放 `index.html`
2. 按上表在目标章里注入错误
3. 运行 `python3 tools/check.py --root <临时目录> --no-report`
4. 确认输出中出现该行"实测输出"，且 exit code 为 1

两个夹具（fixture）陷阱，踩了会看到与注入项无关的 FAIL：

- **漏放 `assets/style.css`** → 每章都报 `资源引用指向不存在的文件：第 7 行 → ../assets/style.css`（资源断链是硬 FAIL，无 `--strict` 豁免）。这是夹具没搭全，不是被测文件有问题。
- **漏放 `index.html`** 不影响章节检查，但 index 相关的检查项自然不会跑。

`BUILD_SPEC.md` 不必复制进临时树——脚本在 `--root` 下找不到时会回落到项目根的 BUILD_SPEC。

改动 check.py 后，**重跑时要核对输出文本，而不是只看 exit code**：exit 1 只说明"有 FAIL"，不说明失败在预期的那一项上（例如夹具缺文件也会让 exit=1）。本表所有"实测输出"列均在 `check_links` 扩展到资源引用之后重新核对过一次。

## tools/wordcount.py（采纳自 writer-05-07，2026-08）

正文汉字计数工具，**独立于 check.py**：BUILD_SPEC §7b.12 规定「脚本与审计不核对时长与字数的换算，只核对存在性」，故 check.py 只查 `.meta` 有无阅读时长（`.meta 未声明阅读时长` → WARN），不做换算校验；wordcount.py 只报事实、不判定通过与否，两者无调用关系。

采纳时改了一处、冻结了一处：

- **改**：时长折算原为无封顶的 `round(字数/350)`，与 §7b.12 不符（22 章里 9 章偏大，如 ch05 报 20 分、ch23 报 21 分，均应为封顶的 18 分）。现按 §7b.12（2026-08 修订）实现 `min(round(字数/350), 18)`，终章固定 8 分。
  - 契约先规定 floor 后改回 round：floor 会让样章 4789 字折出 13 分钟、跌出 §3 的 14–18 带，而标注写的是「阅读 ≈」，round 才自洽。
  - **实现用 `int(n/350 + 0.5)` 而非 Python 内置 `round()`**：内置 round 是银行家舍入，`round(16.5)` 返回 16 而非 17，会在 5775 / 6125 字这类整半点上少报一分钟。
- **冻结**：计数口径（剥离 script/style/svg、排除 #spec/#quiz、数 `[一-鿿]`，计入章头/面包屑/figcaption/页脚预告约 150–250 字固定开销）**不得轻改**——BUILD_SPEC §3 的体量带 4800–7200 字是按这个口径标定的，改口径等于让每章的达标结论整体平移，属于悄悄改契约。要改必须连同体量带一起重标并报 lead。已写进该文件 docstring。

## 流程账：grep 锚点选名词，不选数词（2026-08 立）

修错时要 grep 全部变体（QUALITY §一.6），但**检索词本身也会漏**。本书三次同类翻车：

| 案例 | 检索词 | 漏掉的写法 |
|---|---|---|
| ch08 肺泡数量级 | `数亿` | 「那**几亿**只」（同章、相隔两行） |
| 倍数表述 | `600` | 「**六百**倍」 |
| 图注数字 | 阿拉伯数字 | figcaption 里的中文数字 |

共同病根：**检索词是按"我记得的那个写法"定的，不是按"这个事实可能被写成的所有形式"定的。**

规则：**grep 的锚点选被陈述的那个「名词」，不选数词或形容词。** 数量级说法能有五六种写法（数亿／几亿／上亿／数以亿计／亿万），但被计数的东西只有一个名字，它跑不掉——该搜的是「气球」「肺泡」，不是「数亿」。同理，改「胎盘已下线」时该搜的锚点是「胎盘」，不是「下线」。

不加自动检查（收官不扩检查面），这是人工修错时的操作纪律。
